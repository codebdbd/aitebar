# План модульной архитектуры утилит AiteBar

## 1. Анализ текущего состояния

### Текущая структура
- Все утилиты находятся в одном проекте `AiteBar`
- Зарегистрированы через `UtilityRegistry` в `App.xaml.cs`
- Каждая утилита реализует интерфейс `IUtility`
- Базовый класс `UtilityBase<TWindow>` обеспечивает единый паттерн

### Существующие утилиты
1. **QuickNoteUtility** — быстрые заметки с Markdown
2. **TimerStopwatchUtility** — таймер и секундомер
3. **ColorPickerUtility** — цветовой пикер
4. **FileSorterUtility** — сортировщик файлов
5. **IconConverterUtility** — конвертер иконок

### Проблемы текущей архитектуры
- Сильная связанность: все утилиты в одном проекте
- Ручная регистрация в `App.xaml.cs`
- Нет возможности динамической загрузки
- Сложность добавления новых утилит сторонними разработчиками
- Все утилиты компилируются вместе, увеличивая размер приложения

## 2. Предлагаемая модульная архитектура

### Архитектурные принципы
1. **Изоляция** — каждая утилита в отдельном проекте
2. **Контракты** — общий интерфейс в shared-проекте
3. **Автоматическая регистрация** — поиск и загрузка утилит через reflection
4. **Независимость** — утилиты не зависят друг от друга
5. **Расширяемость** — простое добавление новых утилит

### Предлагаемая структура решения
```
AiteBar.sln
├── AiteBar/                          # Основное приложение
├── AiteBar.Utilities.Abstractions/    # Общие контракты
├── AiteBar.Utilities.QuickNote/       # Модуль QuickNote
├── AiteBar.Utilities.Timer/           # Модуль Timer
├── AiteBar.Utilities.ColorPicker/     # Модуль ColorPicker
├── AiteBar.Utilities.FileSorter/      # Модуль FileSorter
├── AiteBar.Utilities.IconConverter/   # Модуль IconConverter
└── AiteBar.Tests/                     # Тесты
```

## 3. Детали реализации

### 3.1. Проект AiteBar.Utilities.Abstractions

**Назначение:** Содержит общие интерфейсы и базовые классы для всех утилит.

**Содержимое:**
```csharp
// Интерфейс утилиты
public interface IUtility
{
    string Id { get; }
    string DisplayNameKey { get; }
    string IconGlyph { get; }
    string IconColor { get; }
    Task LaunchAsync(AppSettingsService settingsService, Window? owner, 
                     Func<Task>? onBeforeExecute = null);
}

// Базовый класс для утилит с окном
public abstract class UtilityBase<TWindow> : IUtility where TWindow : Window
{
    // Реализация по умолчанию
}

// Атрибут для метаданных утилиты
[AttributeUsage(AttributeTargets.Class)]
public class UtilityAttribute : Attribute
{
    public string Id { get; }
    public string DisplayNameKey { get; }
    public string IconGlyph { get; }
    public string IconColor { get; }
}
```

**Зависимости:**
- `AiteBar.Core` (общие модели: AppSettings, CustomElement и т.д.)

### 3.2. Проект AiteBar.Core (новый)

**Назначение:** Содержит общие модели и сервисы, необходимые утилитам.

**Содержимое:**
- `AppSettingsService`
- `AppSettings`
- `CustomElement`
- `PathHelper`
- `Logger`
- `LocalizationService`
- Другие общие модели

### 3.3. Модули утилит

Каждый модуль утилиты будет отдельным проектом класса библиотеки:

**Пример: AiteBar.Utilities.QuickNote**

**Зависимости модуля:**
- `AiteBar.Utilities.Abstractions`
- `AiteBar.Core`

### 3.4. Система загрузки модулей

**Модульный загрузчик:**
```csharp
public static class ModuleLoader
{
    public static void LoadUtilities(string modulesPath)
    {
        var assemblyFiles = Directory.GetFiles(modulesPath, "AiteBar.Utilities.*.dll");
        
        foreach (var assemblyFile in assemblyFiles)
        {
            var assembly = Assembly.LoadFrom(assemblyFile);
            var utilityTypes = assembly.GetTypes()
                .Where(t => t.IsClass && 
                           t.GetInterface(nameof(IUtility)) != null &&
                           !t.IsAbstract);
            
            foreach (var type in utilityTypes)
            {
                var utility = (IUtility)Activator.CreateInstance(type);
                UtilityRegistry.Register(utility);
            }
        }
    }
}
```

**Автоматическая регистрация:**
```csharp
// В App.xaml.cs
protected override void OnStartup(StartupEventArgs e)
{
    base.OnStartup(e);
    
    // Загрузка модулей из папки Modules/
    var modulesPath = Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "Modules");
    if (Directory.Exists(modulesPath))
    {
        ModuleLoader.LoadUtilities(modulesPath);
    }
    
    // Регистрация встроенных утилит (fallback)
    RegisterBuiltinUtilities();
}
```

## 4. Этапы реализации

### Этап 1: Подготовка (1-2 дня)
1. Создать проект `AiteBar.Core` с общими моделями
2. Создать проект `AiteBar.Utilities.Abstractions`
3. Определить чёткие контракты интерфейсов
4. Настроить зависимости в .csproj файлах

### Этап 2: Выделение общего кода (2-3 дня)
1. Перенести общие модели в `AiteBar.Core`:
   - `AppSettings`, `CustomElement`, `PanelContext`
   - `AppSettingsService`, `PathHelper`, `Logger`
   - `LocalizationService`
2. Обновить ссылки в основном проекте
3. Убедиться, что все тесты проходят

### Этап 3: Создание модулей (3-5 дней)
1. Создать проект для каждой утилиты
2. Перенести код утилит в соответствующие проекты
3. Обновить зависимости
4. Настроить сборку модулей в输出 папку `Modules/`

### Этап 4: Система загрузки (1-2 дня)
1. Реализовать `ModuleLoader`
2. Настроить автоматическую регистрацию
3. Добавить обработку ошибок загрузки модулей
4. Реализовать механизм отключения модулей

### Этап 5: Тестирование и документация (2-3 дня)
1. Написать unit-тесты для `ModuleLoader`
2. Провести интеграционное тестирование
3. Написать документацию для разработчиков утилит
4. Создать шаблон для создания новых утилит

## 5. Преимущества модульной архитектуры

### Для разработчиков
- **Независимая разработка** — каждая утилита разрабатывается отдельно
- **Простое тестирование** — тесты для каждой утилиты изолированы
- **Чёткие контракты** — понятные интерфейсы для взаимодействия
- **Быстрое добавление** — новый модуль не требует изменения ядра

### Для пользователей
- **Уменьшенный размер** — можно установить только нужные утилиты
- **Обновления по отдельности** — обновление одной утилиты не влияет на другие
- **Расширяемость** — возможность добавлять утилиты от сообщества

### Для проекта
- **Масштабируемость** — легче поддерживать растущий код
- **Изоляция ошибок** — крах утилиты не влияет на основное приложение
- **Плагинная система** — возможность создания экосистемы утилит

## 6. Компромиссы и риски

### Преимущества vs Сложность
- ✅ Лучшая модульность → ⚠️ Увеличение количества проектов
- ✅ Независимость → ⚠️ Дублирование некоторых зависимостей
- ✅ Расширяемость → ⚠️ Сложность системы сборки

### Риски и митигация
1. **Сложность сборки** — использовать MSBuild props/targets для общих настроек
2. **Версионирование** — вести семантическое версионирование для каждого модуля
3. **Совместимость** — тесты совместимости при изменении контрактов

## 7. Альтернативные подходы

### Вариант A: Умеренная модульность (рекомендуется)
- Разделение на папки в одном проекте
- Чёткие namespace-границы
- Автоматическая регистрация через атрибуты

**Преимущества:** Простота реализации, минимальные риски  
**Недостатки:** Физически всё в одном проекте

### Вариант B: Полная модульность
- Отдельные проекты для каждой утилиты
- Динамическая загрузка через reflection
- Плагинная архитектура

**Преимущества:** Максимальная гибкость  
**Недостатки:** Высокая сложность, риски совместимости

### Вариант C: Гибридный подход
- Основные утилиты в основном проекте
- Дополнительные утилиты как отдельные модули
- Смешанная регистрация

## 8. Рекомендации

### Начать с умеренной модульности
1. **Разделить по namespace-ам** — каждая утилита в отдельном namespace
2. **Выделить общие модели** — создать `AiteBar.Core`
3. **Автоматизировать регистрацию** — использовать атрибуты и reflection
4. **Документировать контракты** — чёткие интерфейсы для разработчиков

### Постепенная миграция
1. Начать с выделения `AiteBar.Core`
2. Постепенно переносить утилиты в отдельные namespace-ы
3. Добавить автоматическую регистрацию
4. При необходимости — выделять в отдельные проекты

## 9. Критерии успеха

### Функциональные
- ✅ Все существующие утилиты работают без изменений
- ✅ Новые утилиты добавляются без изменения кода ядра
- ✅ Автоматическая регистрация утилит
- ✅ Обратная совместимость с текущими настройками

### Нефункциональные
- ✅ Размер приложения не увеличивается более чем на 10%
- ✅ Время запуска не увеличивается более чем на 50мс
- ✅ Покрытие тестами модульной системы > 80%
- ✅ Документация для разработчиков утилит

## 10. Сроки и ресурсы

### Оценка трудозатрат

- **Система загрузки:** 1-2 дня
