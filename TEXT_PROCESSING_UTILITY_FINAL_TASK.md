# Техническое задание: утилита «Обработка текста» для AiteBar

## 1. Цель

Создать в AiteBar одну встроенную утилиту **«Обработка текста»** с тремя режимами:

1. **Проверка текста**
2. **Типографика**
3. **Очистка текста**

Все режимы работают:

- в одном WPF-окне;
- с одним основным текстовым редактором;
- с одним набором управляющих кнопок;
- через общий механизм AI-подключений AiteBar.

Утилита предназначена для технической обработки текста. Она не должна выполнять редактуру, перевод, пересказ, сокращение, дополнение или стилистическое улучшение.

Главный принцип:

> Исправлять только то, что относится к выбранному режиму, сохраняя смысл, факты, порядок содержания, авторский тон и формулировки.

- переключение между исходным текстом и результатом;

## 3. Архитектура AiteBar

### 3.1. Создаваемые компоненты

Минимальный состав:

- `TextProcessingUtility.cs`;
- `TextProcessingWindow.xaml`;
- `TextProcessingWindow.xaml.cs`;
- `TextProcessingViewModel.cs`;
- `TextProcessingService.cs`;
- `TextProcessingMode.cs`;
- конфигурация системных инструкций;
- тесты.

Точные имена вспомогательных файлов могут быть изменены в соответствии с текущей структурой проекта.

### 3.2. Регистрация утилиты

Класс утилиты должен:

- быть помечен атрибутом `[Utility]`;
- наследоваться от `UtilityBase<TextProcessingWindow>`;
- иметь уникальный идентификатор;
- использовать ключ локализации для названия;
- использовать существующую систему иконок и цветов;
- создавать только одно окно;
- при повторном запуске активировать уже открытое окно.

Рекомендуемый идентификатор:

```csharp
public override string Id => "TextProcessing";
```

Рекомендуемый ключ:

```csharp
public override string DisplayNameKey => "Tool_TextProcessing";
```

### 3.3. Позиционирование окна

При первом запуске использовать существующий механизм AiteBar:

```csharp
window.ShowNearPanel(settingsService);
```

После первого запуска восстанавливать:

- ширину;
- высоту;
- положение;
- состояние `Normal` или `Maximized`.

Состояние `Minimized` не восстанавливать.

Если сохранённая позиция больше не попадает в доступную рабочую область мониторов:

- удалить или проигнорировать сохранённую позицию;
- открыть окно рядом с панелью AiteBar;
- ограничить окно рабочей областью экрана.

### 3.4. Кнопка на панели

Добавить кнопку запуска в `SystemUtilsPanel`.

Обновить все используемые AiteBar точки подключения:

- `MainWindow.xaml`;
- tooltip в `ApplyLocalizedText()`;
- context menu в `AttachSystemUtilityContextMenus()`;
- расчёт числа видимых системных кнопок;
- применение видимости;
- обработчик запуска через `LaunchUtilityAsync`;
- keyboard focus traversal, если системные кнопки участвуют в нём.

### 3.5. Настройка видимости

Добавить в настройки:

```csharp
public bool ShowPresetTextProcessing { get; set; } = true;
```

Подключить:

- чекбокс в разделе быстрых утилит;
- загрузку значения;
- сохранение;
- применение;
- локализацию подписи и описания.

### 3.6. Изоляция ошибок

Исключение внутри утилиты не должно завершать AiteBar.

При необработанной ошибке:

- записать техническую информацию в существующий журнал;
- не записывать исходный или обработанный текст;
- вернуть интерфейс в рабочее состояние, если возможно;
- показать стандартное понятное уведомление.

## 5. Интеграция с AI

### 5.1. Общий принцип

Утилита не обращается к OpenRouter, Cerebras, Google Gemini, Groq, GitHub Models или Mistral AI напрямую.

Все запросы проходят через существующий AI-слой AiteBar, который отвечает за:

- получение списка моделей;
- выбор подключения;
- приоритет подключений;
- quota group;
- cooldown;
- обработку `429`;
- переход к резервному подключению;
- разрешённый fallback;
- запрет автоматического перехода на явно платную модель;
- безопасное получение API-ключа из Windows Credential Manager.

Окно и ViewModel не должны получать или хранить API-ключи.

### 5.2. Явное действие пользователя

Текст отправляется внешнему AI-сервису только после:

- нажатия основной кнопки;
- нажатия `Ctrl+Enter`.

Следующие действия ничего не отправляют:

- открытие окна;
- ввод текста;
- вставка;
- переключение режима;
- выбор модели;
- просмотр исходного текста;
- просмотр результата;
- копирование;
- изменение размера окна.

### 5.3. Информация о передаче данных

Рядом со списком моделей или в его tooltip показать:

> После запуска обработки текст будет отправлен выбранному AI-сервису.

Сообщение не должно занимать отдельный большой блок и не должно повторяться после каждого запроса.

### 5.4. Какие модели показывать

В список включать только модели, которые:

- доступны через сохранённые и проверенные подключения;
- поддерживают текстовый chat/inference;
- принимают системную и пользовательскую инструкции либо совместимый общий формат;
- способны вернуть текстовый ответ;
- не обозначены AiteBar как явно платные;
- имеют достаточный контекст для текущего текста.

Не показывать:

- embedding-модели;
- image-only модели;
- audio-only модели;
- модели без текстового ответа;
- недоступные модели;
- модели с отсутствующим разрешением;
- явно платные модели;
- дубликаты одной и той же логической модели одного сервиса.

### 5.5. Список моделей

Название списка:

**Модель обработки**

Первый пункт:

```text
Автоматически
```

Конкретные модели отображать в формате:

```text
Сервис — модель
```

Примеры:

```text
Cerebras — llama-3.3-70b
Google Gemini — gemini-2.5-flash
Groq — llama-3.3-70b-versatile
```

Если список большой:

- группировать модели по сервису, если текущий WPF-контрол это поддерживает без усложнения;
- не добавлять отдельный поиск в первой версии;
- показывать полное название в tooltip при обрезке.

Недоступные модели в списке не показывать.

### 5.6. Режим «Автоматически»

При выборе `Автоматически`:

- AI-маршрутизатор выбирает доступную бесплатную модель;
- учитывает приоритеты сервисов;
- учитывает quota group;
- может перейти к другому подключению;
- может перейти к другому сервису;
- не может перейти на явно платную модель;
- должен выбрать модель, в контекст которой помещается запрос и ожидаемый ответ.

### 5.7. Конкретная модель

При выборе конкретного пункта:

- фиксируются сервис и модель;
- пользователь не выбирает API-ключ;
- внутри сервиса разрешён переход между подходящими подключениями;
- разрешено использование следующей независимой quota group;
- нельзя незаметно заменить выбранную модель другой;
- нельзя незаметно заменить выбранный сервис другим;
- нельзя перейти на платную модель.

Если выбранная модель недоступна:

- запрос не выполняется другой моделью;
- показывается понятная ошибка;
- пользователь может выбрать другую модель или `Автоматически`.

### 5.8. Сохранение выбора

Сохранять:

- `Автоматически`;
- либо идентификатор сервиса и модели.

При следующем запуске восстановить выбор.

Не сохранять:

- API-ключ;
- конкретное подключение;
- quota group, выбранную для отдельного запроса.

Если сохранённая модель исчезла:

- выбрать `Автоматически`;
- показать стандартное ненавязчивое уведомление:

> Ранее выбранная модель больше недоступна. Включён автоматический выбор.

### 5.9. Отсутствие подключений

Если нет доступных AI-подключений:

- основная кнопка неактивна;
- список моделей показывает пустое состояние;
- отображается сообщение:

> Не добавлена ни одна нейросеть. Добавьте подключение в настройках программы.

Если существующий механизм позволяет, добавить действие:

```text
Открыть настройки
```

Переход:

```text
Настройки программы → Нейросети
```

### 5.10. Безопасность и логи

Запрещено записывать в настройки, логи или телеметрию:

- API-ключи;
- исходный текст;
- обработанный текст;
- содержимое буфера обмена;
- полный AI-запрос;
- полный AI-ответ.

Допустимо логировать:

- режим;
- сервис;
- идентификатор модели;
- длительность;
- код ошибки;
- факт fallback;
- количество символов;
- оценочное количество токенов.

## 6. Поддерживаемые языки текста

Утилита должна корректно работать минимум с:

- русским;
- украинским;
- английским;
- немецким.

Допускается обработка других языков, если модель их поддерживает, но качество вне четырёх обязательных языков не является критерием приёмки.

### 6.1. Определение языка

Язык не выбирается пользователем вручную.

Модель должна определять язык по содержимому и применять правила к каждому фрагменту текста.

### 6.2. Смешанный текст

Если в тексте используются несколько языков:

- не переводить фрагменты;
- не унифицировать весь текст под один язык;
- применять языковые правила к соответствующим фрагментам;
- сохранять технические фрагменты без изменений;
- не менять имена продуктов, команд, файлов, URL и кода.

Пример:

```text
Он открыл файл "report-final.txt" и написал Hello world.
```

Режим проверки может исправить пунктуацию, но не должен:

- переводить `Hello world`;
- менять имя файла;
- типографировать кавычки.

## 7. Ограничение размера текста

### 7.1. Общий принцип

В первой версии автоматическое разбиение текста на части не реализовывать.

Один запуск должен соответствовать одному запросу AI.

### 7.2. Проверка контекста

Перед отправкой оценить размер запроса в токенах.

Необходимо учесть:

- системную инструкцию;
- пользовательский текст;
- служебное обрамление;
- ожидаемый ответ примерно той же длины;
- резерв не менее 15%.

Запрос можно отправлять только если он помещается в контекст выбранной модели.

Для `Автоматически` маршрутизатор должен выбирать только модель с достаточным контекстом.

### 7.3. Жёсткий предел интерфейса

Для первой версии установить максимальный размер введённого текста:

```text
50 000 символов
```

Значение оформить как именованную конфигурационную константу, а не размножать по коду.

Если текст больше:

- не обрезать;
- не отправлять;
- не разбивать;
- показать сообщение:

> Текст слишком длинный. Максимальный размер — 50 000 символов.

Если текст меньше 50 000 символов, но не помещается в выбранную модель:

> Текст не помещается в контекст выбранной модели. Выберите другую модель или сократите текст.

### 7.4. Счётчик

При приближении к пределу после 45 000 символов допускается использовать предупреждающий цвет счётчика, соответствующий дизайн-системе AiteBar.

Сам текст не блокируется при вводе свыше 50 000 символов, но запуск обработки блокируется. Пользователь должен иметь возможность скопировать или сократить текст.

## 9. Размер и поведение окна

### 9.1. Размер по умолчанию

Предпочтительный размер:

- ширина: **1280 px**;
- высота: **840 px**.

Если рабочая область экрана меньше:

- ширина не более 90% рабочей области;
- высота не более 90% рабочей области;
- окно полностью помещается на экране.

### 9.2. Минимальный размер

- ширина: **1000 px**;
- высота: **700 px**.

Ниже этих значений окно не уменьшается.

### 9.3. Максимальная ширина содержимого

Рабочее содержимое не растягивать шире **1600 px**.

На широких экранах:

- центрировать рабочую область;
- равномерно оставлять свободное пространство слева и справа.

### 9.4. Масштабирование

При увеличении ширины растягиваются:

- переключатель режимов;
- описание режима;
- текстовый редактор.

При увеличении высоты растягивается основная рабочая область.

Не растягиваются:

- заголовок;
- высота переключателя;
- ширина боковой колонки;
- размеры боковых кнопок;
- высота нижней панели;
- размеры нижних кнопок.

Прокрутка всего окна не используется.

## 10. Дизайн и размеры

- ресурсы тем;
- стили кнопок;
- стили полей;
- радиусы;
- цвета;
- шрифты;
- иконки;
- focus;
- hover;

Не создавать отдельную визуальную тему.

### 10.1. Внешние отступы

- слева/справа: **32 px**;
- сверху/снизу: **24 px**;

Название:

- **30–32 px**;
- `SemiBold`;
- выравнивание слева.

Описание:

- **15–16 px**;
- вторичный цвет;
- одна строка при стандартной ширине.

Отступы:

- между названием и описанием: **6 px**;
- после описания: **20 px**.

### 10.3. Переключатель режимов

Три равных сегмента:

1. `Проверка текста`
2. `Типографика`
3. `Очистка текста`

- высота: **56 px**;
- каждый сегмент занимает треть ширины;
- иконка: **20–22 px**;
- расстояние до текста: **10 px**;
- текст: **16 px**;
- после блока: **12 px**.

Активный сегмент выделяется стандартным акцентным стилем.

### 10.4. Описание режима

- ширина: вся доступная;
- минимальная высота: **64 px**;
- внутренние отступы: **20 px** по горизонтали и **16 px** по вертикали;
- текст: **15–16 px**;
- максимум две строки;
- после блока: **16 px**.

### 10.5. Рабочая область

Две колонки:

- слева — редактор;
- справа — кнопки.

Расстояние между колонками: **16 px**.

Минимальная высота: **400 px**.

### 10.6. Редактор

- минимальная ширина: **738 px**;
- занимает всё доступное место;
- отступы текста: **24 px** слева/справа, **20 px** сверху/снизу;
- шрифт: **17–18 px**;
- межстрочный интервал: **26–28 px**;
- перенос строк включён;
- горизонтальная прокрутка отключена;

## 15. Формирование AI-запроса

Запрос должен состоять из:

1. системной инструкции выбранного режима;
2. пользовательского текста без дополнительных редакторских указаний.

Не добавлять в пользовательский текст:

- название модели;
- техническую диагностику;
- историю прошлых запросов;
- исходный и предыдущий результат одновременно;
- другие режимы.

Каждый запуск является отдельным stateless-запросом.

Температуру и другие параметры использовать в соответствии с общим AI-слоем AiteBar. Для этой утилиты предпочтительно минимальное или низкое значение вариативности, если провайдер поддерживает параметр.

## 16. Очистка ответа AI

### 16.1. Общий принцип

Основным средством получения чистого результата должна быть системная инструкция.

Постобработка ответа применяется только к очевидному техническому обрамлению.

### 16.2. Разрешено удалить

- один внешний Markdown code fence, если внутри находится весь ответ;
- одну служебную строку перед текстом:
  - `Исправленный текст:`
  - `Оформленный текст:`
  - `Очищенный текст:`
  - `Результат:`
  - локализованные очевидные аналоги;
- внешнюю пару кавычек, только если она охватывает весь многострочный ответ и очевидно добавлена моделью.

### 16.3. Запрещено

- удалять обычные первые или последние строки;
- обрезать содержимое по двоеточию;
- удалять заголовок, который присутствовал в исходном тексте;
- использовать агрессивные регулярные выражения;
- повторно исправлять ответ;
- нормализовать пробелы для всех режимов;
- применять типографику к результату проверки;
- применять грамматическую проверку к результату очистки.

### 16.4. Пустой ответ

Ответ считается пустым, если после удаления технического обрамления он состоит только из пробелов.

В этом случае:

- не заменять текст в редакторе;
- показать ошибку;
- сохранить исходный текст.

## 18. Логика запуска обработки

После запуска:

1. Проверить, что текст не пуст.
2. Проверить лимит 50 000 символов.
3. Проверить наличие доступной модели.
4. Проверить, что запрос помещается в контекст.
5. Сохранить текущий отображаемый текст как `OriginalText`.
6. Сохранить выбранный режим.
7. Сохранить логический выбор модели.
8. Создать `CancellationTokenSource`.
9. Сформировать stateless-запрос.
10. Вызвать общий AI-сервис асинхронно.
11. Заблокировать действия, способные изменить запрос.
12. Дождаться ответа.
13. Проверить ответ.
14. Удалить только очевидное техническое обрамление.
15. Сохранить результат в `ProcessedText`.
16. Показать результат в редакторе.
17. Показать кнопку переключения версий.
18. Активировать `Повторить`.
19. Пересчитать счётчики.

UI не должен зависать.

## 20. Переключение режима

Переключение режима:

- не изменяет текст;
- не отправляет запрос;
- меняет описание режима;
- меняет основную кнопку;
- меняет системную инструкцию следующего запроса.

При следующем запуске обрабатывается текст, который **в данный момент отображается в редакторе**.

Если отображается результат, он становится исходным для следующего режима.

Если отображается первоначальный исходный текст, именно он становится исходным для следующего режима.

Кнопка переключения версий не скрывается только из-за смены режима.

## 21. Последовательная обработка

Пример:

1. Пользователь запускает `Проверка текста`.
2. Получает результат.
3. Оставляет результат отображённым.
4. Переключает режим на `Типографика`.
5. Нажимает `Оформить`.

В этом случае результат проверки становится новым `OriginalText`.

После успешной новой обработки предыдущая пара:

```text
OriginalText / ProcessedText
```

заменяется новой парой.

История цепочки не хранится.

## 22. Ручное редактирование

### 22.1. Редактирование результата

Если пользователь редактирует отображаемый результат:

- изменения записываются в `ProcessedText`;
- `OriginalText` сохраняется;
- переключение версий продолжает работать;
- результат считается пользовательской версией.

### 22.2. Редактирование исходного текста

Если пользователь показывает исходный текст и изменяет его:

- старый `ProcessedText` становится недействительным;
- переключение версий скрывается;
- `Повторить` отключается;
- изменённый текст становится текущим рабочим текстом.

### 22.3. Повтор после ручного изменения результата

Кнопка `Повторить` всегда использует сохранённый `OriginalText`, а не вручную отредактированный результат.

Перед повтором, если результат был изменён вручную, показать подтверждение стандартным механизмом AiteBar:

> Повторная обработка заменит изменённый результат. Продолжить?

Варианты:

- `Повторить`
- `Отмена`

### 22.4. Новый запуск после ручного изменения результата

Если пользователь нажимает основную кнопку, пока отображается вручную изменённый результат:

- именно отображаемый текст становится новым `OriginalText`;
- дополнительное подтверждение не требуется;
- это считается последовательной обработкой.

## 23. Поведение кнопок

### 23.1. Вставить

Боковая кнопка `Вставить`:

- активна при наличии текстового содержимого в буфере;
- полностью заменяет текущий текст;
- не вставляет в позицию курсора;
- сбрасывает старый результат;
- скрывает переключение версий;
- отключает `Повторить`.

Стандартное `Ctrl+V` в редакторе работает как обычная вставка в позицию курсора.

### 23.2. Копировать

- копирует весь отображаемый текст;
- неактивна при пустом поле;
- после копирования может показать стандартное краткое подтверждение.

### 23.3. Повторить

Повторяет последнюю успешную обработку:

- с сохранённым `OriginalText`;
- в сохранённом режиме;
- с сохранённым логическим выбором модели.

Конкретный API-ключ не фиксируется.

### 23.4. Очистить

Сбрасывает:

- редактор;
- исходный текст;
- результат;
- переключение версий;
- повтор;
- счётчики.

Не сбрасывает:

- режим;
- выбранную модель;
- размер окна;
- положение окна.

После очистки фокус возвращается в редактор.

## 24. Состояния интерфейса

### 24.1. Пустое поле

- основная кнопка неактивна;
- `Копировать` неактивно;
- `Повторить` неактивно;
- `Очистить` неактивно;
- переключение версий скрыто;
- счётчики нулевые.

### 24.2. Текст введён

- `Копировать` активно;
- `Очистить` активно;
- основная кнопка активна при доступной модели и допустимом размере;
- `Повторить` зависит от предыдущей успешной обработки.

### 24.3. Текст превышает лимит

- редактор остаётся доступен;
- копирование и очистка доступны;
- основная кнопка неактивна;
- счётчик отображает предупреждающее состояние;
- показывается tooltip или сообщение о лимите.

### 24.4. Выполняется запрос

Заблокировать:

- редактор;
- переключатель режимов;
- список моделей;
- боковую кнопку `Вставить`;
- `Очистить`;
- `Повторить`;
- переключение версий.

Основная кнопка превращается в:

**Отменить**

Повторное выполнение исключено.

### 24.5. Успешный результат

- показать результат;
- сохранить исходный текст;
- показать переключение версий;
- включить `Повторить`;
- обновить счётчики;
- вернуть фокус в редактор.

### 24.6. Ошибка

- не терять исходный текст;
- не подставлять частичный ответ;
- вернуть UI в рабочее состояние;
- сохранить режим и выбор модели;
- показать стандартное уведомление AiteBar.

### 24.7. Отмена

- отменить запрос через `CancellationToken`;
- не подставлять частичный результат;
- восстановить текст, отображавшийся до запуска;
- вернуть UI в рабочее состояние.

## 25. Закрытие окна

Текст между запусками не сохраняется.

Если редактор пуст, окно закрывается без подтверждения.

Если редактор содержит текст, но пользователь не менял его после последней успешной обработки, окно закрывается без подтверждения.

Если есть несохранённый вручную введённый или изменённый текст, использовать существующий общий механизм AiteBar для подтверждения закрытия.

> Закрыть окно? Введённый текст не сохраняется.

Кнопки:

- `Закрыть`
- `Отмена`

Не создавать отдельный нестандартный дизайн диалога.

## 32. Тестовые примеры

Тесты AI не требуют полного побуквенного совпадения во всех допустимых случаях. Они должны проверять обязательные ограничения режима и отсутствие запрещённых изменений.

### 32.1. Проверка текста

#### Пример 1

Исходный текст:

```text
Он сказал "я вернусь" но не уточнил когда.
```

Ожидаемый результат:

```text
Он сказал "я вернусь", но не уточнил, когда.
```

Обязательно:

- обычные кавычки сохранены;
- слова не заменены;
- двоеточие после `сказал` не добавлено.

#### Пример 2

Исходный текст:

```text
Ми перевірили документ але помилку не знайшли.
```

Ожидаемый результат:

```text
Ми перевірили документ, але помилку не знайшли.
```

#### Пример 3

Исходный текст:

```text
This files contains two error.
```

Ожидаемый результат:

```text
This file contains two errors.
```

#### Пример 4

Исходный текст:

```text
Версия app-1.2.0 работает но файл C:\Temp\report-final.txt не найден.
```

Ожидаемый результат:

```text
Версия app-1.2.0 работает, но файл C:\Temp\report-final.txt не найден.
```

Обязательно сохранить версию и путь.

#### Пример 5

Исходный текст:

```text
Напиши на test@example.com если вопрос не решится...
```

Ожидаемый результат:

```text
Напиши на test@example.com, если вопрос не решится...
```

Обязательно сохранить три точки.

### 32.2. Типографика

#### Пример 1

Исходный текст:

```text
Он сказал "я вернусь" - и ушел...
```

Ожидаемый результат для русского фрагмента:

```text
Он сказал «я вернусь» — и ушел…
```

Слова `ушел` не исправлять на `ушёл`, поскольку это не типографика.

#### Пример 2

Исходный текст:

```text
Цена 100 грн, скидка 20 %, температура 25 ° C.
```

Ожидаемый результат:

```text
Цена 100 грн, скидка 20 %, температура 25 °C.
```

Допускаются неразрывные пробелы согласно правилам реализации.

#### Пример 3

Исходный текст:

```text
Страницы 10 - 15.
```

Ожидаемый результат:

```text
Страницы 10–15.
```

#### Пример 4

Исходный текст:

```text
Открой "C:\Temp\report-final.txt" и перейди на https://example.com/a-b.
```

Путь и URL не изменять.

#### Пример 5

Исходный текст:

```text
He opened "report-final.txt" - потом закрыл файл.
```

Не переводить. Имя файла сохранить. Типографику применять к языковым фрагментам без повреждения технического текста.

### 32.3. Очистка текста

#### Пример 1

Исходный текст:

```text
Это предложение было
разорвано внутри строки.
```

Ожидаемый результат:

```text
Это предложение было разорвано внутри строки.
```

#### Пример 2

Исходный текст:

```text
Документ содер-
жит важный текст.
```

Ожидаемый результат:

```text
Документ содержит важный текст.
```

#### Пример 3

Исходный текст:

```text
Первый абзац.


Второй абзац.
```

Ожидаемый результат:

```text
Первый абзац.

Второй абзац.
```

#### Пример 4

Исходный текст:

```text
1. Первый пункт
2. Второй пункт
```

Список должен сохраниться.

#### Пример 5

Исходный текст:

```text
Файл report-final.txt
находится в C:\Temp\
и доступен по https://example.com/a-b.
```

Не повреждать имя файла, путь и URL. Не исправлять язык или пунктуацию.
